# pentest-env

An isolated penetration testing and CTF environment, packaged as a Nix flake. Run `nix develop` inside the repository to get every tool. When you leave the shell, nothing is left on your `PATH`, and the host system configuration is never modified.

## 1. Overview

- Tools grouped by pentest methodology phase (OSINT → scanning → web → exploitation → passwords → post-exploitation → network → reverse engineering → forensics → utilities).
- **Two profiles**: `light` (~7 GiB, 2-3 tools per phase) and `full` (~20-30 GiB, extended arsenal with advanced tools).
- Firefox pre-configured with uBlock Origin via enterprise policies.
- CTF workspaces generated by script; wordlists downloaded on demand.
- HTB/THM VPN (OpenVPN) started inside a **dedicated network namespace**, without touching the host's WireGuard.
- Graphical applications (Burp Suite, Wireshark, Ghidra, Firefox) using the host's display server.

## 2. Prerequisites

### NixOS

- Flakes enabled in your system configuration:

  ```nix
  nix.settings.experimental-features = [ "nix-command" "flakes" ];
  ```

- Working `sudo` (only used by `ctf-vpn`).

### Other distributions (Ubuntu, Debian, Fedora, Arch, ...)

1. Install Nix in multi-user mode (with the daemon). Either the official installer:

   ```bash
   sh <(curl -L https://nixos.org/nix/install) --daemon
   ```

   or the Determinate Systems installer, which enables flakes by default:

   ```bash
   curl --proto '=https' --tlsv1.2 -sSf -L https://install.determinate.systems/nix | sh -s -- install
   ```

2. If you used the official installer, enable flakes by adding this line to `/etc/nix/nix.conf`:

   ```
   experimental-features = nix-command flakes
   ```

   Then restart the daemon: `sudo systemctl restart nix-daemon`.

3. Check the installation with `nix --version`.
4. Make sure `sudo` is installed and your user can run it (`ctf-vpn` relaunches itself through `sudo -E`).
5. Graphical applications (Burp Suite, Wireshark, Ghidra, Firefox) may need [nixGL](https://github.com/nix-community/nixGL) to get OpenGL working outside NixOS. Packet capture requires root, as described in section 8.

### Common requirements

- Disk space:
  - **Light profile**: about **3.2 GiB to download** and **7 GiB unpacked**.
  - **Full profile**: about **10-15 GiB to download** and **20-30 GiB unpacked**.
  - Plus wordlists (`minimal` ≈ 15 MB, `full` ≈ 1 GB+ for SecLists).
- Optional: [direnv](https://direnv.net/) to enter the devShell automatically.

## 3. Installation

```bash
git clone <repository-url> pentest-env
cd pentest-env
```

### Light profile (default)

```bash
nix develop
```

### Full profile

```bash
nix develop .#full
```

With direnv (light profile by default, edit `.envrc` to use `use flake .#full` for the full profile):

```bash
direnv allow
```

The first `nix develop` downloads and builds the environment, which takes several minutes. Subsequent runs are instant.

## 5. Commands and aliases

Defined in the devShell (shared rc file, also injected into the VPN namespace):

| Command | Effect |
|---|---|
| `ctf-new <name>` | Alias for `ctf-init`: creates a CTF workspace |
| `ctf-ls` | Lists existing workspaces |
| `serve <port>` | Python HTTP server on the given port (default 8000) |
| `listen <port>` | Netcat listening on the given port |
| `ctf-vpn <start\|shell\|status\|stop>` | Manages the isolated VPN (see section 8) |
| `ctf-htb <file.ovpn>` | Shortcut: `ctf-vpn start` then `ctf-vpn shell` |
| `fetch-wordlists <minimal\|full>` | Downloads wordlists and linpeas |
| `ctf-tmux [session]` | Attaches to or creates a tmux session (default `ctf`) on a dedicated server |

Environment variables:

- `PENTEST_ROOT`: repository root
- `PENTEST_WORDLISTS`: `$PENTEST_ROOT/wordlists`
- `PENTEST_WORKSPACE`: `~/ctf-workspaces`
- `PENTEST_RC`: shared rc file (prompt, aliases, functions)
- `PENTEST_PROFILE`: active profile (`light` or `full`)

The prompt shows `[CTF:LIGHT]` or `[CTF:FULL]` in red, or `[CTF:VPN:LIGHT]` / `[CTF:VPN:FULL]` inside the VPN namespace.

### Panes and windows (tmux)

Run `ctf-tmux` inside the devShell to open a tmux session. Every pane starts a bash with the devShell environment, prompt, aliases and functions, so you never need to run `nix develop` again.

The tmux server runs on its own socket (`-L pentest`), separate from any tmux you run outside the project. The config is generated by Nix and does not touch `~/.tmux.conf`. Mouse support is enabled and windows and panes are numbered from 1.

Default prefix is `Ctrl+b`, then:

| Keys | Action |
|---|---|
| `%` | Split the pane to the right |
| `"` | Split the pane below |
| `Arrow keys` | Move between panes |
| `z` | Zoom the current pane (toggle) |
| `x` | Close the current pane |
| `c` | New window |
| `n` / `p` | Next / previous window |
| `d` | Detach (the session keeps running) |

To reattach later, run `ctf-tmux` again from a devShell. If you change the devShell (new store paths after a `flake.lock` update, for example), stop the old server first with `tmux -L pentest kill-server`, otherwise new panes keep the old environment.

## 6. Wordlists

```bash
fetch-wordlists minimal   # rockyou.txt only (~15 MB compressed)
fetch-wordlists full      # rockyou + full SecLists collection (~1 GB+)
```

Files are placed in `wordlists/` (gitignored). The script is idempotent: files already present are not downloaded again. `linpeas.sh` is placed in `tools/` in both modes.

## 7. Creating a CTF workspace

```bash
ctf-new htb-machine-x
```

Directory layout created in `~/ctf-workspaces/htb-machine-x/`:

```
scans/     # nmap, masscan, gobuster… output
exploits/  # scripts and PoCs
loot/      # retrieved files (user.txt, root.txt, creds…)
notes/     # notes.md with a report template
```

Names accept letters, digits, `.`, `_` and `-`. Running the command again on an existing workspace does not modify it.

## 8. Isolated VPN (`ctf-vpn`)

### The problem

The host is permanently connected to a WireGuard tunnel. To reach HTB or THM machines, a second VPN (OpenVPN) is needed. Starting it on the host would break the WireGuard routing, so the CTF VPN runs inside a separate **network namespace**.

### How network namespaces are used

A network namespace is an isolated copy of the Linux network stack: interfaces, routing table, iptables rules and ports are all private to it. The `ctf-vpn` script:

1. Creates the `pentest-ns` namespace and a pair of virtual interfaces `veth`: `veth-host` (10.200.1.1/24) on the host side and `veth-pentest` (10.200.1.2/24) inside the namespace.
2. Routes the namespace to the host at `10.200.1.1` as its default gateway.
3. Adds a **dedicated routing table** (table 100) and a rule `from 10.200.1.0/24 lookup 100`: traffic from the namespace leaves through the physical interface (default route excluding `wg*`, `tun*`, `veth*`), never through WireGuard. This rule has a higher priority than the `wg-quick` rules.
4. Enables NAT (`MASQUERADE`) on the physical interface, along with the matching `FORWARD` rules.
5. Writes a `resolv.conf` to `/etc/netns/pentest-ns/`. `ip netns exec` mounts it automatically on `/etc/resolv.conf` inside the namespace.
6. Starts OpenVPN **inside** the namespace and waits for `Initialization Sequence Completed` in the log.

All of this requires root: `ctf-vpn` relaunches itself through `sudo -E`.

### Commands

```bash
ctf-vpn start ~/Downloads/lab.ovpn   # creates the namespace, starts OpenVPN
ctf-vpn shell                        # shell inside the namespace (prompt [CTF:VPN:…])
ctf-vpn status                       # state of the namespace, routes and VPN
ctf-vpn stop                         # stops OpenVPN and removes everything it created
ctf-htb ~/Downloads/lab.ovpn         # start + shell in one command
```

`start` is idempotent: if the VPN is already active, it reports it and exits successfully. If the namespace exists without an active VPN, it asks you to run `stop` first. If OpenVPN fails, the script cleans everything up through a `trap EXIT`, including on Ctrl+C.

The namespace shell inherits the devShell environment: PATH, aliases and functions (via `PENTEST_RC`), `DISPLAY`, `WAYLAND_DISPLAY`, `XAUTHORITY`, `XDG_*`. It runs with your user's UID, not as root.

### Typical workflow

```bash
cd pentest-env
nix develop           # or nix develop .#full
ctf-htb ~/Downloads/lab.ovpn     # HTB VPN inside the namespace
# inside the [CTF:VPN:…] shell:
nmap 10.10.10.x                  # traffic goes through the HTB VPN
exit                             # back to the host
ctf-vpn stop                     # cleanup
```

Meanwhile, the host's WireGuard keeps working normally.

### Known limitations

- **DNS**: the namespace uses `1.1.1.1` and `9.9.9.9`. `.htb` or `.thm` names do not resolve. Add the hosts to `/etc/netns/pentest-ns/hosts` (mounted automatically inside the namespace) or use IP addresses directly.
- **Graphical interface**: Wayland works. X11 applications that use abstract sockets may fail, because those sockets are specific to each namespace.
- **Wireshark** inside the namespace only sees the namespace's traffic, which is usually what you want.
- **Root capture**: `tcpdump` and `wireshark` need root to capture. `sudo` uses its own `secure_path` and does not see the devShell's PATH. Use `sudo "$(command -v tcpdump)"` or `sudo -E "$(command -v wireshark)"`. Without `programs.wireshark.enable` in the NixOS configuration (which this project does not modify), capturing from the GUI therefore requires root.

## 9. Usage tips

- Before starting an HTB machine, create a workspace with `ctf-new <name>`, then save the scans in `scans/`.
- Use `masscan` to quickly find open ports, then `nmap -sCV -p <ports>` for details.
- For a web target: `whatweb`, then `gobuster` or `ffuf`, then Burp Suite as a proxy (`127.0.0.1:8080`). For forms, use `sqlmap -r request.txt`.
- For hashes: `hashid <hash>` to identify the type, then `john` or `hashcat -m <mode>`.
- For Linux privesc: run `linpeas.sh` from `tools/`, transferred via `serve` and `curl`.
- For binaries: `checksec` through `pwndbg` in gdb, `r2`, or `ghidra`.
- For pivoting: `chisel server` on the attacker machine and `chisel client` on the target.
- **Full profile extras**: `proxychains-ng` for tunnelling through SOCKS proxies, `nuclei` for automated vuln scanning with templates, `impacket` for Windows protocol attacks (secretsdump, psexec, etc.), `yara` for malware triage.

## 10. Adding a tool to the flake

1. Check that the package exists: `nix search nixpkgs#<name>`.
2. Add the name to the list of the relevant phase in `nix/tools.nix`:
   - In the base `groups` section if it belongs in the light profile.
   - In the `extraGroups` section if it belongs only in the full profile.
   - Add a comment if the choice is not obvious.
3. If the package is not in nixpkgs: write an expression in `nix/` (template: `nix/arsenal.nix`), or install it with pip into a venv from the shellHook in `nix/shell-hook.nix`.
4. Verify with `nix flake check --no-build`, then `nix develop` (or `nix develop .#full`).
5. Update `flake.lock` only when needed: `nix flake update <input>`.

After a change, run `git add` before `nix develop`: nix only takes into account files tracked by git.

## Repository structure

```
flake.nix               # main flake and devShells (light + full)
flake.lock              # pinned versions
nix/
  tools.nix             # tools by phase, profile-aware (light/full)
  arsenal.nix           # arsenal (available in nixpkgs)
  netns.nix             # ctf-vpn packaging with its network dependencies
  shell-hook.nix        # scripts, rc file, banner (profile-aware)
scripts/
  ctf-init.sh           # CTF workspace creation
  ctf-vpn.sh            # isolated VPN in a namespace
  fetch-wordlists.sh    # wordlists and linpeas
wordlists/              # gitignored, filled by fetch-wordlists
tools/                  # gitignored, linpeas.sh
.envrc                  # direnv: use flake
```

## Technical decisions

| Topic | Choice | Reason |
|---|---|---|
| Profiles | `light` (default) / `full` | Two devShells from the same flake; no duplication, `nix develop .#full` for the extended arsenal |
| Firefox | `wrapFirefox` + enterprise policies | uBlock Origin pre-installed at first launch, no manual setup |
| `smbclient` | `samba` package | No `smbclient` attribute in nixpkgs |
| `ncat` | Provided by `nmap` | No `ncat` attribute in nixpkgs |
| `linpeas` | Downloaded by `fetch-wordlists` | Not in nixpkgs; avoids versioning the script in the repository |
| `pwndbg` | `pwndbg/pwndbg` flake input | Not in nixpkgs |
| `hashid` | Preferred over `hash-identifier` | Python 3, simpler to maintain |
| `snmpcheck` + `net-snmp` | Both | `snmp-check` does structured enumeration, `snmpwalk` does raw queries |
| `seclists` | Outside the flake | Several GB; optional download into `wordlists/` |
| Arsenal | Available in nixpkgs | `nix/arsenal.nix` re-exports the package |
| Scripts | `writeShellApplication` | Adds `set -euo pipefail` and runs shellcheck at build time |
| Platform-specific packages | Filtered with `availableOn` | For example, burpsuite only exists on x86_64 |
| `impacket` / `scapy` | Python packages (full only) | Added to `python3.withPackages` in full profile |
